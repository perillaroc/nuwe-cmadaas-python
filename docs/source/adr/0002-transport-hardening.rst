传输层加固与请求日志策略
==========================

状态
----

已接受（2026-09-15）。

背景
----

兼容客户端需要保留 MUSIC 的原始 URL 表示和现有底层返回语义，同时为测试、连接复用、错误诊断和文件下载提供可控的传输层能力。通用 URL 编码会改变部分 MUSIC 服务依赖的字节表示，因此 URL 拼接和签名不能委托给通用查询字符串编码器。

决策
----

``CMADaaSClient`` 和 ``Connection`` 支持注入 ``Session`` 或实现 ``get`` 方法的 transport。未注入时继续使用 ``requests``，保留既有构造方式和底层响应对象。

MUSIC 参数编码、签名 canonical 串和最终 URL 分别由 ``music.protocol`` 中的纯函数完成。参数保持兼容的原样 ``key=value`` 文本；密码类参数不得作为公开 MUSIC 参数拼接。签名可以使用内部密码，但密码不进入 URL。

请求日志策略通过 ``log_policy`` 配置：

* ``full``（默认）：记录实际发送的完整签名 URL，维持兼容客户端的排障能力；
* ``redacted``：在 URL 视图中隐藏 ``userId``、``sign`` 和密码类字段；
* ``summary``：只记录 interface、service node、request id、耗时、结果码和重试次数。

客户端只生成一次 URL，日志使用同一字符串；任何策略都不记录密码。应用可以在构造客户端时选择策略，底层请求内容不随日志策略改变。

所有请求使用连接和读取超时。默认最多重试 2 次，采用 ``0.1 * 2 ** (n - 1)`` 秒退避；只重试连接失败、读取超时和幂等读取中的 HTTP 502/503/504。``callAPI_to_saveAsFile`` 这类可能产生服务端副作用的请求显式关闭重试。认证、参数、解码和其他 HTTP 错误不自动重试。

文件下载使用 ``stream=True`` 与 ``iter_content``，先写入目标目录下的 ``.part`` 临时文件，完成后使用原子替换。下载失败会删除临时文件并保留原有目标文件。默认保持原有覆盖行为，也可通过 ``overwrite=False`` 拒绝覆盖。服务端文件名必须是单一安全文件名，禁止 ``.``、``..``、斜杠和反斜杠。

后果
----

离线测试可以使用注入的 transport 精确验证 URL、超时、重试和文件生命周期，而无需网络。应用生产环境可以关闭敏感的完整 URL 日志；选择 ``redacted`` 或 ``summary`` 会牺牲部分 MUSIC 排障信息，但不会改变签名和请求。下载失败仍以兼容错误码返回，严格高层入口通过现有结构化异常映射为下载或传输异常。
